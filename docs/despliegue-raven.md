# Publicación controlada de Raven

Este procedimiento separa la integración de Git, la actualización de Laragon y la publicación en Cloud. La automatización de GitHub solo compila y prueba; no contiene comandos de publicación, migraciones reales ni secretos. Un preflight correcto no autoriza por sí solo una migración o un despliegue.

## Antes de fusionar o publicar una rama

1. En Laravel Cloud, abra cada entorno de Raven y anote su rama vinculada. Consulte **Settings → Deployments** para comprobar **Push to deploy**, **Deploy hook** y los comandos del entorno. No comparta la URL del hook ni valores de variables. Revise **Settings → Preview environments** para descartar que abrir, actualizar o fusionar un PR active un entorno automático que use recursos empresariales. Revise también los workflows y servicios externos que llamen a hooks.
2. Si una operación de Git desencadena un despliegue o una automatización no comprobada, deténgala hasta que el propietario apruebe y verifique la protección. No basta con que el repositorio no tenga un workflow de despliegue.
3. Verifique los SHA y el diff de los PR. Fusione Promotora con un merge que conserve los commits, cambie la base del PR apilado de Coordinadora a `main` y compruebe nuevamente su diff antes de fusionarlo. Publique un solo PR para el bloque administrativo final. No use force-push ni squash para esta integración.

Referencias: [Despliegues y hooks](https://laravel.com/cloud/docs/deployments), [Configuración de entornos](https://laravel.com/cloud/docs/environments) y [Automatizaciones de vista previa](https://laravel.com/cloud/docs/preview-environments).

## Laragon habitual

Actualice el checkout habitual solo tras confirmar que `main` contiene la integración y que el árbol está limpio. Use `git fetch origin`, cambie a `main` y actualice con `git merge --ff-only origin/main`. No descarte modificaciones, no cambie los otros worktrees y no reutilice el `vendor` o los assets de una demo. Ejecute `composer install`, `npm ci --ignore-scripts` y `npm run build`. Limpie solamente cachés compiladas con `config:clear`, `route:clear` y `view:clear` cuando corresponda. Evite vaciar sesiones o la caché empresarial.

Con la conexión habitual confirmada como local, verifique recuentos e historial, el journal de normalización y la lista de migraciones. Guarde un respaldo completo fuera de Git, calcule sus huellas y compruebe su restauración en una instancia separada. `php artisan raven:pharmacy-requests-preflight --json` comprueba solicitudes existentes; si encuentra conflictos, revise los registros con la propietaria. No cambie estados históricos para hacer pasar las restricciones.

| Migración | Efecto esperado |
|---|---|
| `2026_10_31_000001_add_review_constraints_to_pharmacy_requests_table` | Agrega restricciones CHECK de solicitudes en MySQL. Requiere preflight sin conflictos. |
| `2026_11_03_000001_add_coverage_and_audit_to_pharmacy_assignments` | Agrega campos e índices para cobertura y auditoría. Las asignaciones existentes conservan su identidad e historial. |
| `2026_11_04_000001_create_commercial_catalog_options_table` | Crea el catálogo comercial vacío. Las opciones observadas se incorporan mediante revisión y confirmación explícitas de Coordinadora. |
| `2026_11_04_000002_add_explanation_rule_to_visit_reasons` | Agrega un indicador nullable. Los motivos anteriores conservan su regla histórica. |
| `2026_11_04_000003_create_establishment_imports_table` | Crea la tabla privada de manifiestos Excel y su confirmación. No importa ningún archivo. |

Antes de aplicar una migración real, obtenga autorización para las rutas exactas, compruebe que sus huellas y el respaldo siguen vigentes y repita el preflight. No use `migrate:fresh`, `db:wipe`, seeders de demostración ni `composer setup` sobre una base existente. Después verifique `route:list --path=coordinator`, login, solicitudes, asignaciones, cronogramas y evidencias. La sincronización del checklist inicial es una operación de datos separada: requiere simulación vigente, respaldo y autorización expresa. No se ejecuta en el arranque ni en la publicación.

## Laravel Cloud, después de la autorización

- **Runtime y compilación.** Seleccione PHP 8.4, Node 24 para compilar y las extensiones PDO MySQL, mbstring, OpenSSL, DOM, XMLReader, ZIP y Fileinfo. Instale desde los lockfiles con `composer install --no-dev --prefer-dist --no-interaction --optimize-autoloader`, `npm ci --ignore-scripts` y `npm run build`. No añada comandos de migración automática al build o a los deploy hooks. Verifique límites HTTP de carga superiores a 10 MB por archivo y espacio temporal privado; compruebe los límites efectivos de PHP/FPM y del proxy con un archivo ficticio próximo al límite.
- **MySQL y sesiones.** Use MySQL administrado con entorno de validación separado. Confirme que el esquema y las conexiones pertenecen al entorno correcto. Use sesiones y caché compartidas (`database` o Redis compatible) para que no dependan de una instancia efímera. Verifique política de respaldo, retención, restauración y ventana de cambios antes de ejecutar DDL. Conserve por separado las claves necesarias para recuperar campos cifrados existentes.
- **Evidencias.** Utilice un bucket privado S3 compatible, con el adaptador incluido. Mantenga `VISIT_EVIDENCE_DISK=visit_evidence` y configure el alias `visit_evidence` como disco privado persistente. Puede usar el disco administrado del mismo nombre o, con conexión S3 explícita, `VISIT_EVIDENCE_DRIVER=s3` y los parámetros del bucket en secretos de Cloud. Las evidencias guardan el nombre del disco y la ruta: si ya existen, copie y verifique los objetos por tamaño y SHA-256 antes de cambiar el alias, conservando `files/…` y los identificadores. No haga público el bucket, no use enlaces públicos permanentes ni cambie las referencias de las visitas. Pruebe una descarga autorizada y el rechazo desde otra cuenta. El fichero Excel temporal se elimina después de usarlo y sus manifiestos se conservan en la base privada. `raven:establishment-exports:prune` simula la limpieza de archivos vencidos; `--apply` elimina solo esas exportaciones temporales, no catálogos ni historiales.
- **Correo y HTTPS.** Verifique el dominio remitente en Resend, configure `MAIL_MAILER=resend`, remitente autorizado y la clave como secreto. No envíe correo a cuentas reales durante QA. Configure el subdominio con los registros DNS indicados por Cloud, espere TLS válido, use `APP_URL=https://…`, `APP_ENV=production`, `APP_DEBUG=false`, `SESSION_SECURE_COOKIE=true` y un `APP_KEY` protegido. HTTPS permite probar captura puntual de ubicación en los dispositivos del laboratorio. La aplicación no hace seguimiento continuo.
- **Salud, errores y consumo.** Configure `/up` como comprobación de disponibilidad y revise adicionalmente una ruta autenticada que use la base y el almacenamiento; `/up` por sí sola no comprueba esos recursos. Restrinja acceso a logs, configure avisos de fallos y alertas de consumo en el panel de la organización. Revise los tiempos de respuesta y el tamaño de las cargas con datos representativos. Defina un límite de gasto con la responsable de operación antes de habilitar un corte de cómputo.
- **Validación y recuperación.** Ejecute `php artisan raven:deployment-preflight --database --json` en el entorno autorizado para comprobar requisitos y migraciones sin imprimir secretos. Valide cada rol con cuentas ficticias, solicitudes, coberturas y sustituciones, planificación, checklist, GPS, evidencias privadas, Excel e indicadores. Si el despliegue falla, detenga la publicación, conserve logs privados y recupere el último código compatible. Si hubo DDL o cambios de datos, evalúe restauración verificada por separado; revertir el código no revierte el esquema.

Referencias: [Runtimes](https://laravel.com/cloud/docs/runtimes), [almacenamiento de objetos](https://laravel.com/cloud/docs/resources/object-storage), [dominios y TLS](https://laravel.com/cloud/docs/domains), [Laravel Mail y Resend](https://laravel.com/framework/docs/13.x/mail), [avisos de Cloud](https://laravel.com/cloud/docs/notifications) y [límites de gasto](https://laravel.com/cloud/docs/spending-limits).

## Verificación continua

`composer test` inicia SQLite en memoria sin cargar `.env`. Para MySQL, el arranque requiere el indicador explícito de prueba, el esquema descartable, `127.0.0.1:13329` y la verificación de su directorio de datos. El workflow usa un servicio desechable de MySQL separado. Las pruebas de restricciones específicas de un motor se omiten únicamente en el otro motor.
